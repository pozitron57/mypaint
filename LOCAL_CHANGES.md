# Локальная версия MyPaint для онлайн-уроков

Состояние сохранено 15 ноября 2026 года из работающей установки macOS.
Задача форка — хранить используемые изменения, их историю и отличие от оригинала.
Публикация исходников не меняет установленную программу и не требует её перезапуска.

## Какая копия запускается

Команда `mypaint` запускает `/usr/local/bin/mypaint`. Приложение
`/Applications/MyPaint.app` — оболочка Automator, которая запускает тот же файл.
Он использует Python 3.11 из Homebrew и загружает код из
`/usr/local/lib/mypaint/`. Ресурсы находятся в `/usr/local/share/mypaint/`.

Отдельная старая папка исходников `.local/bin/mypaint` в этом запуске не участвует.
Для работы программы локальный клон этого форка не требуется.

- `codex/teaching-board` — точное сохранение изменённых исходников установленной
  версии плюс описание отличий и контрольные суммы.
- Основа этой ветки — оригинальный коммит
  [`b07b90589c24978750e204b0311a81ff74fd0f47`](https://github.com/mypaint/mypaint/commit/b07b90589c24978750e204b0311a81ff74fd0f47)
  от 5 февраля 2024 года. Он указан в установленном запускном файле как
  `2.1.0-alpha+git.b07b9058`.
- Код существующей ветки `master` оставлен на базе
  `35aa9d33cd3deba6cafea6d8fc901b5a1d161ceb`; в её README добавлена ссылка на
  рабочую ветку и это описание. Рабочий код нужно брать из `codex/teaching-board`.
- Существующая ветка `fix/layout-independent-shortcuts` и её коммит `23fa8bd1`
  также сохранены. Это другая, более поздняя по исходной базе реализация
  клавиатурного патча из PR №1327.

Рабочая сборка намеренно не перенесена на новую базу: такое обновление требует
отдельной проверки поведения планшета, полноэкранного режима и клавиатуры.
Сравнивать именно личные правки следует с `b07b9058`, а не с `master`:

## Отличия от оригинала

| Правка | Файлы | Поведение и ограничения |
| --- | --- | --- |
| Совместимость с PyGObject | `gui/sliderwidget.py`, `lib/glib.py` | Используются `prop.get_default_value()` и `k.name` вместо старых обращений к свойствам. Эти две правки уже были в установленной копии; точная история их внесения неизвестна. |
| Горячие клавиши и раскладки | `gui/keyboard.py`, `gui/accelmap.py`, новый `gui/keyboardutils.py` | На macOS учитывается текущая раскладка, затем физическое расположение стандартных ANSI-US клавиш. В редакторе сочетаний нелатинские клавиши без Option предпочитают физическое соответствие; Option-символы можно назначать явно. В установленном варианте сохранён старый обход с группой 1 для Windows. |
| Панели в полноэкранном режиме | `gui/workspace.py` | Наведение на край или место скрытого плавающего окна не раскрывает интерфейс. Переключение по Tab сохраняется. Флаг `Workspace.AUTOHIDE_POINTER_REVEAL = False`; `True` возвращает прежнее поведение. |
| Вставка под курсор | `gui/document.py` | При вставке по горячей клавише берётся текущая позиция указателя в координатах рисунка, а не позиция последнего события мыши. Это устраняет смещение после изменения расположения холста. |
| Системное меню macOS | `gui/drawwindow.py` | Меню приложения дублируется в системную строку через `GtkosxApplication`. Выход из Dock или системного меню проходит через обычное сохранение MyPaint. Требуется `gtk-mac-integration`; без него правка пропускается. |
| Заголовок в полноэкранном режиме macOS | `gui/drawwindow.py` | Скрывается содержимое служебного окна `NSToolbarFullScreenWindow`. Системная строка меню сохраняется, обычный оконный заголовок остаётся. Нужен PyObjC. Это обход через внутреннее имя класса macOS, поэтому после обновления системы его может потребоваться пересмотреть. Флаг `MACOS_HIDE_FULLSCREEN_TITLEBAR = False` возвращает заголовок. Для выхода из полноэкранного режима остаются F11 и пункт меню View. |
| Скорость трекпада | `gui/mode.py` | `_PIXELS_PER_SMOOTH_SCROLL_UNIT = 25.0 / 4`: плавный сдвиг и Ctrl+прокрутка для масштаба в четыре раза медленнее. Пошаговая прокрутка обычного колеса и прокрутка с Shift не меняются. |

Каждая группа сохранена отдельным коммитом; два изменения `drawwindow.py`
разделены с помощью промежуточной резервной копии, оставшейся в установке.
Изменённые исходники перенесены без переписывания и форматирования.

## Связь с PR №1142 и №1327

[`mypaint/mypaint#1142`](https://github.com/mypaint/mypaint/pull/1142) — более
ранняя чужая попытка исправить нелатинские сочетания. На дату проверки это
открытый черновик, не включённый в upstream. Установленный патч не является
точной копией этого PR.

[`mypaint/mypaint#1327`](https://github.com/mypaint/mypaint/pull/1327) — PR из
этого аккаунта с клавиатурным патчем. Он закрыт без включения в upstream.
Его исходники и 12 тестов остались в ветке `fix/layout-independent-shortcuts`.
Вариант, фактически установленный на компьютере, отличается от PR: например,
он иначе выбирает сочетание в редакторе и сохраняет специальную обработку
Windows. Здесь сохранён именно установленный вариант. Результаты тестов
из PR №1327 нельзя автоматически приписывать этой версии.

Часть личных правок подготовлена с помощью AI. Этот форк сохраняет их как
личную сборку; наличие кода в форке не означает принятия или проверки
разработчиками MyPaint.

## Что было проверено при сохранении

- Сопоставлены все обычные установленные файлы в `gui/` и `lib/`, имеющие
  соответствие в исходном коммите. Найдено восемь изменённых файлов и один
  добавленный исходник `gui/keyboardutils.py`.
- Резервные копии до правок клавиатуры, панелей, вставки, меню и прокрутки
  совпадают с соответствующими файлами исходного коммита.
- Все 158 проверенных установленных исходников и ресурсов совпадают с этой
  веткой побайтово. Все девять изменённых и добавленных файлов сохранены; их SHA-256
  записаны в [манифесте](doc/teaching-board-source-manifest.json).
- Выполнены проверка синтаксиса Python этих девяти файлов и `git diff --check`.
- Программа при сохранении исходников не перезапускалась; новая визуальная
  проверка планшета, меню или жестов не проводилась. Это фиксация уже работающего
  кода, а не новый выпуск с повторным тестированием интерфейса.

Готовая библиотека `_mypaintlib`, сгенерированные `lib/config.py` и
`lib/mypaintlib.py`, кэши, личные настройки, кисти пользователя и рисунки не
добавлены. Исполняемый запускной файл и оболочка Automator также не переносятся:
они остались в установленной программе, а в форке хранится исходный `mypaint.py`.

## Как получить исходники и отслеживать следующие правки

Для получения полной исходной версии:

```sh
git clone --branch codex/teaching-board https://github.com/pozitron57/mypaint.git
cd mypaint
```

Это создаёт папку исходников и не меняет установленную программу. Для сборки
см. [BUILDING.md](BUILDING.md); понадобятся нативные зависимости MyPaint.
Две необязательные интеграции macOS дополнительно используют
`gtk-mac-integration` и PyObjC. Форк не содержит готового установщика.

Для отдельного файла с личными правками:

```sh
git diff b07b90589c24978750e204b0311a81ff74fd0f47 HEAD -- gui lib > teaching-board.patch
```

Этот патч рассчитан на указанную исходную версию. Применение к более новой
версии может потребовать разрешения конфликтов и повторной проверки.

Для будущих изменений удобнее сначала править исходники в клоне, сохранять
понятный коммит и отправлять его в форк, затем обновлять установленную копию.
Если правка снова сделана прямо в `/usr/local/lib/mypaint/`, её нужно отдельно
перенести в клон и опубликовать: GitHub не отслеживает установленную папку
автоматически. Перед переустановкой стоит сверить её с сохранёнными исходниками.
Личные настройки и рисунки требуют отдельной резервной копии.
